# Solar Launcher V0.5 - Game Adapter Foundation

V0.5 starts the transition from a universal file/patch loader to a framework that can understand supported games through trusted Game Adapters.

## First adapter: Cuphead Wii U

Verified target metadata from the extracted installation:

- Title ID: `0005000021000000`
- Title version: `0`
- executable: `Unity-master.rpx`
- Unity/Mono managed gameplay: `Assembly-CSharp.dll`
- reserved experimental Player 3 id: `2`

## Test 1: Mono compile trace

The first V0.5 test deliberately does **not** create Player 3 yet.

Instead, the Cuphead Adapter registers a FunctionPatcher hook for the RPX symbol `mono_compile_method`. When Cuphead compiles selected managed gameplay classes, Solar records the managed method pointer and the resulting native PowerPC code pointer.

Classes currently traced:

- `PlayerManager`
- `PlayerInput`
- `AbstractPlayerController`
- `PlayerCameraController`
- `Level`
- `LevelHUD`
- `LevelHUDPlayer`

This gives the project real runtime addresses before invasive P3 hooks are attempted.

## Safety

The metadata helper addresses used by the trace were taken from the symbol table of the supplied Cuphead `Unity-master.rpx`. Before calling them, Solar validates the first instructions of all four helpers. If the bytes do not match, metadata tracing is disabled instead of calling an unknown address.

The FunctionPatcher hook itself is restricted to:

- Title ID `0005000021000000`
- title version `0`
- executable `Unity-master.rpx`
- function name `mono_compile_method`

## Test mod

Copy `examples/Cuphead3PlayerTest` to:

```text
SD:/wiiu/SolarLauncher/games/0005000021000000/Cuphead3PlayerTest/
```

The patch manifest requests:

```text
cuphead.mono.compileTrace
```

After launching Cuphead, inspect `SD:/wiiu/SolarLauncher/logs/solar.log` for lines beginning with `Mono Trace:`.

## Next step

Once the runtime addresses for the player systems are confirmed on real hardware, the next test will target the smallest safe P3 path: extend/create the runtime player slot and invoke the existing generic player creation path with Player ID `2`. Input, HUD, camera, revive and targeting will then be added incrementally.
